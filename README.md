# Hydrovoltaic ML

This repository contains the curated data, machine-learning analyses, and figure/table production workflow for the manuscript *Transport-Controlled Performance in Hydrovoltaic Energy Harvesting: A Data-Driven Assessment Using Interpretable Machine Learning*.

## Data scope

The canonical processed dataset is [`data/processed/hydrovoltaic_dataset_phase2_input_utf8.csv`](data/processed/hydrovoltaic_dataset_phase2_input_utf8.csv). It contains 159 literature records and 52 columns. The main target is the estimated power density derived from open-circuit voltage and short-circuit current density. Of the 159 records, 112 have observed internal-resistance values and 108 have positive reported power-density values.

The source curation workbook is [`data/raw/hydrovoltaic_data.xlsx`](data/raw/hydrovoltaic_data.xlsx). CSV files in `notebooks/` include earlier Phase-1 datasets and a compatibility copy of the Phase-2 dataset; they are not the canonical final dataset.

## Repository map

- `data/`: raw curation input and the canonical processed dataset.
- `notebooks/01`–`03`: data cleaning, early validation, and construction of the Phase-2 input.
- `notebooks/04`–`11`: main modeling, robustness, interpretation, resistance, and virtual-design analyses.
- `notebooks/12`–`17`: production workflows for manuscript Figures 1–6.
- `notebooks/18`: numerical cross-checks for manuscript-reported values.
- `notebooks/21`–`22`: Supporting Information tables and figures.
- `scripts/`: figure assembly and final-paper robustness workflows.
- `results/`: canonical numerical outputs, final figure panels, Supporting Information outputs, and retained revision-era scientific robustness analyses.

The `results/revision/R1C2`, `R1C6`, and `R3C3` directories are retained because those analyses substantively support the final scientific claims; they are not merely peer-review correspondence.

## Reproduction path

Run notebooks with the repository root available as the project root; several historical notebooks are most reliable when launched from `notebooks/`. Do not overwrite saved results unless intentionally reproducing that analysis.

1. Inspect the raw-to-curated workflow in `notebooks/01_data_cleaning.ipynb` through `notebooks/03_modeling_v7_validation.ipynb`. The final analysis input is the canonical CSV in `data/processed/`.
2. Reproduce the main model comparison with `notebooks/04_modeling_phase2_models.ipynb` and robustness analyses with `notebooks/05_modeling_phase2_robustness.ipynb`.
3. Reproduce observed-resistance and resistance-aware analyses with notebooks `08`, `11`, `15`, and `16`.
4. Reproduce explicit-descriptor and virtual-design analyses with notebooks `09`, `10`, and `17`.
5. Generate main-figure panels with notebooks `12`–`17`; Figure 1A is generated by `scripts/draw_figure_1a.py`.
6. Validate reported numerical values with notebook `18` and `results/paper_numbers/`.
7. Generate Supporting Information tables and figures with notebooks `21` and `22`.
8. Use the scripts named `run_r1c2_*`, `run_r1c6_*`, and `run_r3c3_*` for the retained final-paper robustness analyses.

Most panels are exported programmatically in PDF, SVG, and PNG form. Some final multi-panel manuscript assemblies were completed in Adobe Illustrator and are therefore not reproduced by a single script. Figure 3 and parts of the Supporting Information also contain displayed summaries transcribed from upstream result tables; validate those values against the canonical CSV outputs rather than treating plotting literals as independent analyses.

## Python environment

The release environment, including Python and package versions, is pinned in [`environment.yml`](environment.yml). Create and activate it with:

```bash
conda env create -f environment.yml
conda activate hydrovoltaic-ml
jupyter lab
```

The environment contains only packages imported by the notebooks and supporting scripts, plus the Jupyter runtime.

## Interpretation

The dataset is heterogeneous and literature-derived, with incomplete reporting for some descriptors. The virtual-design results are model-based screening of descriptor combinations, not experimentally validated device predictions.
